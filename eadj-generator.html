Step 1 — Case header

Fill in the memo header. Case number is text — leading zeros are kept.

Step 2 — Scraper prompt

Download the prompt. Feed it, with the plan documents, to your LLM. The LLM returns JSON. You upload that JSON in Step 3.

What to attach to the LLM

  • Plan document, amendments, restatements, union contracts (all eras)
  • R5 Preliminary Plan Summary
  • PF factor sets, per era
  • §436 Evaluation, with its IPS number
  • Participant data (SPECTRUM download from TRMD)
  • Estimated asset figure from the auditor
  • NRAD Pension Information Profile (Funded GL Ratio)
  • Earnings Offsets Summary, if any
  • Employee Contributions Processing Evaluation (TP 36), if any
  • Successor Plan Determination (TP 61), if any

Do not attach the DEL or the E.Adm memo. They are not E.Adj inputs. The 4022(c) amount is never paid as an estimated benefit.

Welcome

  
This app writes the Estimated Benefits Adjustment Analysis memo for a terminated plan. It follows the 2024 template, version of 11/25/2024.

  

    
How it works

    
    
      
  1. Case header — memo addresses, case number, plan name, BPD, DOPT, DOTR.
    2. 
      
  2. Scraper prompt — download the prompt; feed it with the plan documents to your LLM (Microsoft Copilot in the office, any LLM at home).
    3. 
      
  3. JSON import — upload the JSON the LLM returns. The app validates it against the schema.
    4. 
      
  4. Review — check all 9 sections, approve each one. The §9 conclusion is a suggestion; you choose the final box.
    5. 
      
  5. Download — the filled memo as <case>EAdj.docx, plus inputs JSON and audit log.
    6. 
    

    
The LLM never writes the memo and never decides an ambiguous answer. The app validates, you review, only approved JSON generates the document. No LLM is in the calculation path.

Help

  

    
What do I attach to the LLM?

    
See Step 2. The plan documents, R5, PF factors, §436 Evaluation, participant data, estimated assets, NRAD PIP, plus the Earnings Offsets Summary, TP 36 evaluation, or TP 61 determination if any apply. Do not attach the DEL or the E.Adm memo.

  

  

    
The JSON failed validation. What now?

    
Read the error list in Step 3. It names the missing or wrong field. Fix the JSON in the text box and validate again, or ask the LLM to fix the named fields. Common causes: a missing section, a §3 or §6 outcome spelled wrong, a §9 checkbox missing, or a table row missing SSN or name.

  

  

    
How is the §9 conclusion decided?

    
The app suggests a conclusion: impacted by assets if one or more of 9.1–9.4 is checked, or 9.5 applies and the Funded GL Ratio is 80% or higher. Not impacted if none of 9.1–9.4 is checked, or 9.5 applies and the ratio is below 80%. You choose the final box in Step 4. The memo shows the box you chose.

  

  

    
How does §6.2 work?

    
Answer all six screening questions. All No means no determination is needed (outcome 6.2). Any Yes means a determination is needed (outcome 6.3). N/A is allowed only for the substantial-owner and majority-owner questions, when no benefit was provided for that owner.

  

  

    
Where does my data go?

    
Nowhere. This is a single file opened from disk. It makes no network calls, stores nothing on a server, and never sends your data anywhere. Inputs stay in your browser until you download them.
